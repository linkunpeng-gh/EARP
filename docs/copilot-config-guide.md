# EARP 平台配置指南

本文档为 EARP 管理后台各配置页面提供参数说明和最佳实践，供 AI 配置助手参考。

---

## 1. 模型配置 (Models)

### 推理模型 (LLM)

推理模型用于所有 AI 推理任务，包括：
- 知识库问答的回复生成
- 工作流编排的意图解析
- 数据域和知识库的描述生成
- Query Understanding (QU) 升级

**推荐配置：**
- **本地部署 (Ollama)**：适合对数据安全要求高的场景。推荐 qwen3.5:35b 或更大参数模型。
- **云端 API (OpenAI/DeepSeek)**：适合对延迟敏感或需要高质量生成的场景。推荐 gpt-4o 或 deepseek-chat。

**注意事项：**
- 更换 LLM 模型后，建议测试默认模型连接是否正常
- QU 升级模板通常不需要修改，除非有特殊的查询理解需求

### 嵌入模型 (Embedding)

嵌入模型用于将文本转换为向量，是知识库检索的核心。

**推荐配置：**
- **bge-m3:latest**：支持多语言，适合中文为主的场景
- **text-embedding-3-small**：OpenAI 的轻量级嵌入模型，性价比高

**重要提醒：**
- 更换嵌入模型后，已有知识库需要重新索引（Reindex）
- 不同嵌入模型产生的向量维度不同，不可混用

### 重排序模型 (Rerank)

重排序模型用于对检索结果进行二次排序，提升检索精度。为可选组件。

**推荐配置：**
- **bge-reranker-v2-m3**：支持多语言，效果好
- 未配置时系统使用 RRF 混合排序，基本够用

## 2. 知识库管理 (Knowledge Base)

### 分块策略

分块（Chunking）将长文档拆分为适合检索的小段。

**分块大小 (chunk_size)：**
- 建议范围：500-1500 tokens
- 过小：丢失上下文，检索结果碎片化
- 过大：降低检索精度，可能包含无关信息
- 默认 1000 tokens 适合大多数场景

**分块重叠 (chunk_overlap)：**
- 建议：分块大小的 10%-20%
- 作用：防止语义在分块边界处断裂
- 默认 200 tokens

**分隔符 (separator)：**
- 默认 `\n\n`（段落分隔）适合结构化文档
- 对于 Markdown 文档，可使用 `## ` 或 `### ` 按标题分块
- 对于纯文本，可使用 `\n` 或 `。` 按句分块

### 检索策略

**检索模式：**
- **向量搜索 (vector)**：纯语义匹配，适合概念性查询
- **混合搜索 (hybrid)**：向量 + 全文检索 RRF 融合，推荐使用

**Top K：**
- 建议范围：3-10
- 过多：增加 LLM 上下文长度，可能引入噪声
- 过少：可能遗漏相关文档
- 默认 5 适合大多数场景

**相似度阈值 (score_threshold)：**
- 建议范围：0.3-0.5
- 过高：导致无结果返回
- 过低：引入不相关结果
- 默认 0.3 适合起步阶段

## 3. AI 应用配置 (Chat App)

### 系统提示词 (System Prompt)

好的系统提示词应包含以下要素：

1. **角色定义**：明确 AI 的身份（如"你是企业知识库智能助手"）
2. **任务描述**：说明 AI 应该做什么（如"基于提供的资料回答用户问题"）
3. **约束条件**：定义行为边界（如"资料不足时明确说明，不要编造"）
4. **输出格式**：指定回答风格（如"回答用中文，简洁清晰"）

**示例：**
```
你是企业知识库智能助手。请基于提供的资料准确回答用户问题；
资料不足时明确说明，不要编造。回答用中文，简洁清晰。
```

### 知识库范围 (KB Scope)

- **不选择**：自动路由到相关知识库（推荐）
- **选择特定知识库**：限定检索范围，适合场景单一的应用

### 检索参数

检索参数控制每次对话时检索哪些相关内容：

- **retrieval_top_k**：每次检索的文本块数量，建议 3-5
- **retrieval_threshold**：过滤低相关性结果，建议 0.3
- **retrieval_mode**：推荐 hybrid 模式

### 生成参数

生成参数控制 AI 的回复行为：

- **temperature**（温度）：0=确定性回复，1=创造性回复。配置类任务建议 0.3，创意类任务建议 0.7
- **top_p**：核采样参数，通常保持默认 0.9
- **max_tokens**：最大输出长度，根据预期回答长度设置，通常 1024-2048
- **context_turns**：保留最近 N 轮对话历史，建议 3-5 轮

## 4. 数据域 (Data Domain)

### 数据域的作用

数据域是 EARP 的数据治理边界，用于：
- **权限隔离**：不同数据域的知识库对不同角色可见
- **语义路由**：系统根据查询自动匹配相关数据域
- **分类管理**：按业务领域组织知识库

### 数据分类

- **public**：公开信息，所有用户可见
- **internal**：内部信息，仅授权角色可见
- **confidential**：机密信息，需要严格权限控制
- **restricted**：受限信息，最高安全等级

### 路由描述

路由描述用于语义路由匹配（50-150字），会被向量化后与用户查询匹配。

**编写建议：**
- 覆盖该数据域下所有知识库的主题
- 使用自然语言描述，避免技术术语
- 包含常见的查询关键词

## 5. 角色与权限 (Roles)

### 权限体系

EARP 使用 RBAC（基于角色的访问控制）：
- 每个角色有一组权限（如 session.create、capability.invoke）
- 用户通过角色获得权限
- Admin 角色拥有所有权限，跳过数据域过滤

### 数据域访问

角色的 data_domain_access 决定了该角色可以访问哪些数据域下的知识库：
- 不设置：无法访问任何数据域
- 设置特定数据域：只能访问这些数据域下的知识库
- Admin 角色：自动拥有所有数据域访问权限
