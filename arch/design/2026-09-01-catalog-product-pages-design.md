## 1. Catalog 治理中心（catalog-admin.html）

### 1.1 页面定位

Catalog 治理的统一入口，提供：统一查看（只读聚合）、引用注册、pack 管理、manifest 管理、审批中心。**不提供语义定义编辑**（语义编辑在各源系统页面）。

### 1.2 页面结构

```
┌─────────────────────────────────────────────────────────────┐
│ 页面标题：Catalog 治理                                        │
│ 副标题：统一查看 · 引用注册 · Pack 管理 · Manifest 管理 · 审批  │
├─────────────────────────────────────────────────────────────┤
│ [Tab: 统一查看] [引用注册] [Pack 管理] [Manifest 管理] [审批中心] │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  (Tab 内容区)                                                │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 1.3 Tab 1：统一查看

**功能**：从各源系统聚合全部 10 种对象，只读浏览和搜索。

**筛选栏**：

| 筛选项 | 控件 | 说明 |
|---|---|---|
| kind | 下拉多选 | data_domain / entity_type / relation_type / metric / unit / aggregation / time_window_schema / binding_template / capability_contract / rule_schema |
| data_domain | 下拉 | 生产域 / 安全域 / 设备域（从 Profile 配置读取） |
| status | 下拉 | active / deprecated / inactive / 全部 |
| 源系统 | 下拉 | Ontology / 指标管理 / 基础配置 / 能力中心 / 绑定模板 |
| 搜索 | 文本框 | 按 stable_id / 显示名模糊搜索 |

**列表字段**：

| 列 | 说明 |
|---|---|
| stable_id | 稳定标识（如 `coal.raw_coal_output`） |
| kind | 对象类型 |
| 显示名 | 业务名称（如"原煤产量"） |
| version | 当前版本 |
| status | active（绿）/ deprecated（黄）/ inactive（灰） |
| 源系统 | 对象定义所在系统 |
| 最新版本 | 源系统最新版本号；若高于已注册版本，标红"可升级" |
| 操作 | 查看详情 / 注册引用（仅 active 且未注册） |

**操作**：
- 查看详情：弹窗展示对象完整定义、版本历史、被哪些 pack 引用
- 注册引用：跳转"引用注册"Tab，预填该对象

**权限**：`ecmc.catalog.read`（所有认证用户）

### 1.4 Tab 2：引用注册

**功能**：将源系统对象注册为 Catalog 引用，锁定版本和 content_hash。

**已注册引用列表**：

| 列 | 说明 |
|---|---|
| stable_id | 稳定标识 |
| kind | 对象类型 |
| 注册版本 | 锁定的版本号 |
| content_hash | SHA-256（前 8 位 + 复制按钮） |
| status | active / deprecated / inactive |
| 注册时间 | — |
| 所属 pack | 被哪些 pack 引用（可点击跳转） |
| 操作 | 升级版本 / 停用 / 查看详情 |

**注册新引用**（按钮 → 弹窗三步）：

1. **选择源系统和 kind**：下拉选择源系统 → 下拉选择 kind
2. **搜索选择对象**：从源系统拉取 active 对象列表，搜索选择
3. **选择版本并确认**：展示对象详情和可选版本（默认最新），确认注册 → 锁定 version + content_hash

**版本升级**：
- 列表中"最新版本"列标红时，点击"升级版本"→ 弹窗展示当前版本与最新版本的差异（字段级 diff）→ 确认升级 → 产生 pack 新版本（若该引用在 pack 中）
- 升级不自动生效到 manifest，需发布新 manifest 后才生效

**停用引用**：
- 点击"停用"→ 二次确认 → status 改为 inactive → 触发 LKG 策略（已 active 模型继续服务+告警，新引用拒绝）
- 停用后不可删除，保留审计记录

**权限**：查看=`ecmc.catalog.read`；注册/升级/停用=`ecmc.catalog.request`（提交后走审批流）

### 1.5 Tab 3：Pack 管理

**功能**：创建和管理行业包/企业包，组合引用，发布版本，导出/导入。

**Pack 列表**：

| 列 | 说明 |
|---|---|
| pack_id | 如 `coal-mining-industry` |
| 层级 | 行业包 / 企业包（平台基础包在此页只读展示，不可新建） |
| 当前版本 | 如 `1.2.0` |
| 条目数 | 引用数量 |
| content_hash | SHA-256（前 8 位） |
| 状态 | draft / published / deprecated |
| 操作 | 查看 / 编辑 / 发布新版本 / 导出 / 版本历史 |

**新建 Pack**（按钮 → 弹窗）：

| 字段 | 控件 | 说明 |
|---|---|---|
| pack_id | 文本输入 | 小写英文/下划线/中划线，创建后不可改 |
| 名称 | 文本输入 | 显示名称 |
| 层级 | 单选 | 行业包 / 企业包 |
| 描述 | 文本域 | 可选 |

**Pack 详情页**（点击查看/编辑进入）：

- **基本信息**：pack_id、名称、层级、描述、owner
- **引用列表**：已加入的引用（stable_id、kind、version、status），可增删
  - 添加引用：从已注册引用中选择（弹窗，支持 kind 筛选和搜索）
  - 移除引用：二次确认（若该 pack 已 published，移除产生新版本）
- **版本历史**：version、发布时间、发布人、变更说明、content_hash
- **操作按钮**：保存草稿 / 发布新版本 / 导出

**发布新版本**：
- 点击"发布新版本"→ 弹窗填写版本号（自动建议 MAJOR.MINOR.PATCH）和变更说明 → 确认 → 计算 content_hash → 状态变为 published
- 已 published 的 pack 不可修改，变更必须发布新版本

**导出**：
- 点击"导出"→ 下载 `.earppack` 文件（ZIP 格式，含 manifest.json + entries/ 目录）
- 导出内容：pack 元数据 + 全部引用的 canonical input
- **导出权限（FROZEN）**：仅 pack owner（创建者角色）或平台管理员可导出。企业 canonical input 可能包含敏感业务口径，不允许所有认证用户导出。导出操作记录审计日志（操作人、pack_id、version、时间）。

**导入**（Phase 2，Phase 1 不实现）：
- Phase 1 仅支持导出，不支持导入。导入涉及签名验证、租户隔离、ZIP Slip 防护、重复 stable_id 处理、schema migration 等安全问题，推迟到 Phase 2。
- Phase 2 设计：上传 `.earppack` → 签名验证 → 预览条目 → 租户可见性检查 → 确认导入 → 创建新 pack 或合并。

**权限**：查看=`ecmc.catalog.read`；新建/编辑/发布=通过角色绑定配置；导出=pack owner 或平台管理员（非所有认证用户）；导入=平台架构负责人角色

### 1.6 Tab 4：Manifest 管理

**功能**：管理生效的 manifest，选择 pack 组合，发布和回滚。

**当前生效 Manifest**（卡片展示）：

| 字段 | 说明 |
|---|---|
| manifest_id | 如 `coal.sdrh.jqmk.production` |
| revision | 如 `3` |
| Pack 组合 | 平台基础包 v1.0.0 + 煤矿行业包 v1.2.0 + JQMK 企业包 v1.0.0 |
| 条目总数 | effective manifest 去重后的引用数 |
| manifest_hash | SHA-256（前 8 位 + 复制按钮） |
| 生效时间 | — |
| 签署人 | — |
| 操作 | 查看详情 / 发布新 revision / 回滚 |

**发布新 revision**（按钮 → 弹窗三步）：

1. **选择 Pack 组合**：勾选要包含的 pack 和版本（平台基础包必选，行业包/企业包可选）
2. **预览 Effective Manifest**：展示组合后的引用列表（去重）、条目总数
   - **冲突检测（FROZEN）**：同一 `(kind, stable_id, version)` 在多个 pack 中出现且 content_hash 不同时，标记为冲突，**禁止发布**（fail closed）。不允许高层级覆盖低层级。
   - 企业定制必须使用新的 stable_id 或新的 version，不得复用同版本覆盖语义。
   - 相同 `(kind, stable_id, version)` 且 hash 一致的条目，去重保留一份。
3. **确认发布**：计算 manifest_hash → 提交签署（CatalogChangeRequest）→ 审批通过后生效

**回滚**：
- 点击"回滚"→ 选择历史 revision → 预览差异 → 确认 → 产生新 revision（内容等于历史版本），不直接修改历史
- 回滚也走审批流

**历史版本列表**：

| 列 | 说明 |
|---|---|
| revision | 版本号 |
| Pack 组合 | 各 pack 及版本 |
| manifest_hash | — |
| 生效时间 | — |
| 签署人 | — |
| 操作 | 查看详情 / 回滚到此版本 |

**权限**：查看=`ecmc.catalog.read`；发布/回滚=`ecmc.catalog.manifest.publish`（走审批流）

### 1.7 Tab 5：审批中心

**功能**：CatalogChangeRequest 的审批管理。

**筛选栏**：待我审批 / 我提交的 / 全部；状态（draft / submitted / approved_pending_fulfillment / fulfilled / fulfillment_failed / rejected / cancelled）

**申请列表**：

| 列 | 说明 |
|---|---|
| 申请 ID | 如 `CCR-20260901-001` |
| 类型 | 引用注册 / 引用升级 / 引用停用 / pack 发布 / manifest 发布 / pack 导入 |
| 申请人 | — |
| 申请时间 | — |
| 状态 | draft（灰）/ submitted（黄）/ approved_pending_fulfillment（蓝）/ fulfilled（绿）/ fulfillment_failed（红）/ rejected（红）/ cancelled（灰） |
| 操作 | 查看详情 / 批准 / 驳回 / 重试履约 / 取消（仅 submitted 且我是申请人或审批人） |

**审批操作**：
- 批准：填写审批意见 → 状态变为 `approved_pending_fulfillment` → 目录服务自动履约 → `fulfilled`；履约失败 → `fulfillment_failed`，可重试履约
- 驳回：填写驳回原因 → 状态变为 `rejected` → 申请人可修改后重新提交（新申请 ID）
- 取消：申请人可取消 `submitted` 状态的申请 → `cancelled`
- 重试履约：`fulfillment_failed` 状态可由管理员重试履约

**separation-of-duties（SoD）与应急**：
- 审批人不能审批自己提交的申请。
- 若唯一审批人也是申请人（小团队一人兼任多角色），系统自动路由到**候补审批人**（Profile 中配置的 backup_approver）。
- 若候补审批人也不可用，提供 **break-glass 紧急审批**：需双人确认（申请人 + 另一位管理员），全程审计，事后必须补签正式审批。
- break-glass **仅作为审计标记**（audit_logs 中 `emergency=true`），不新增业务状态。请求经双人授权后仍进入 `approved_pending_fulfillment`，遵循正常状态机。

**权限**：查看自己的申请=`ecmc.catalog.read`；审批=`ecmc.catalog.approve`

## 2. 项目配置（profiles.html）

### 2.1 页面定位

项目级 Catalog 配置管理。创建和编辑 Profile，定义项目的 scope、角色绑定、变更单等。**Profile 是项目配置，不是产品硬编码**——不同项目可配置不同的行业、租户、角色。

### 2.2 页面结构

列表页 + 新建/编辑弹窗（或独立编辑页）。

```
┌─────────────────────────────────────────────────────────────┐
│ 页面标题：项目配置                                             │
│ 副标题：管理各项目的 Catalog 配置（scope / 角色 / 变更单）       │
│                                          [+ 新建项目配置]      │
├─────────────────────────────────────────────────────────────┤
│ 筛选：行业下拉 / 状态下拉 / 搜索框                              │
├─────────────────────────────────────────────────────────────┤
│ 列表：profile_id | 名称 | 行业 | 租户 | 数据域 | 角色数 | 状态 │
│       | 创建时间 | 操作（编辑/查看/复制）                       │
└─────────────────────────────────────────────────────────────┘
```

### 2.3 列表页

**筛选栏**：

| 筛选项 | 控件 |
|---|---|
| 行业 | 下拉（coal_mining 等） |
| 状态 | 下拉（draft / active / deprecated） |
| 搜索 | 文本框（按 profile_id / 租户 / 企业名模糊搜索） |

**列表字段**：

| 列 | 说明 |
|---|---|
| profile_id | 如 `jqmk-coal-production` |
| 名称 | 显示名称（如"金桥煤矿生产域"） |
| 行业 | coal_mining |
| 租户 | JQMK |
| 数据域 | 生产域（多个时逗号分隔） |
| 角色数 | 已配置角色数量 |
| 状态 | draft（灰）/ active（绿）/ deprecated（黄） |
| 创建时间 | — |
| 操作 | 编辑 / 查看详情 / 复制 |

### 2.4 新建/编辑表单

**基本信息区**：

| 字段 | 控件 | 必填 | 说明 |
|---|---|---|---|
| 名称 | 文本输入 | 是 | 显示名称 |
| industry_scope | 下拉选择 | 是 | 行业（coal_mining 等，可扩展） |
| enterprise_scope | 文本输入 | 是 | 企业（如 SDRH） |
| tenant_id | 文本输入 | 是 | 租户（如 JQMK） |
| data_domain | 单选 | 是 | **一 Profile 一 domain**。从数据域列表选择一个。多 domain 项目创建多个 Profile |

**系统自动生成（只读展示）**：

| 字段 | 生成规则 |
|---|---|
| profile_id | `{tenant}-{industry}-{domain}`，如 `jqmk-coal-production` |
| catalog_profile_id | `{industry}.{enterprise}.{tenant}.{domain}`，如 `coal.sdrh.jqmk.production` |

**角色绑定区**（可配置，不硬编码）：

| 字段 | 控件 | 说明 |
|---|---|---|
| 角色列表 | 动态行 | 每行：角色名称（文本，可自定义）+ 绑定人员（人员选择器）+ 联系方式（文本，可选）+ 删除按钮 |
| 添加角色 | 按钮 | 新增一行角色绑定 |

> 角色名称由项目自定义（如"产品负责人""平台架构""运维"等），数量不限，一人可兼任多角色。系统提供常用角色建议（可一键添加）。

**变更单区**：

| 字段 | 控件 | 说明 |
|---|---|---|
| 变更单号 | 文本输入 | 如 JQMK-BG-20260901-001 |
| 发布单号 | 文本输入 | 如 JQMK-FB-20260901-001 |

**其他**：

| 字段 | 控件 | 说明 |
|---|---|---|
| 记录保管人 | 人员选择器 | — |
| pack_lock | 只读展示区 | 展示当前绑定的 pack 及版本/hash，由 pack 管理流程自动填入，不可手动编辑 |

### 2.5 操作流

**新建**：
1. 点击"新建项目配置"→ 弹窗填写基本信息 + 角色绑定 + 变更单
2. 保存 → 状态为 draft → 系统生成 profile_id / catalog_profile_id
3. 完成 pack 组合和 manifest 发布后，可签署生效 → 状态变为 active

**编辑**：
1. 点击"编辑"→ 修改字段 → 保存 → 产生 Profile 新版本
2. 已 active 的 Profile 修改后，已生效的 manifest 仍绑定旧版本，不自动升级（版本不可变）

**复制**：
1. 点击"复制"→ 基于已有 Profile 创建新配置（预填所有字段，可修改）
2. 用于快速创建类似项目的配置

**停用**：
1. active 状态的 Profile 可停用 → 状态变为 deprecated
2. 停用后该项目的 manifest 不再接受新发布，已生效的继续运行

### 2.6 权限

| 操作 | 权限 |
|---|---|
| 查看列表/详情 | 所有认证用户 |
| 新建/编辑/复制 | 平台管理员 |
| 停用 | 平台管理员 |

## 3. 指标管理（metrics.html）

### 3.1 页面定位

指标（metric）的语义定义管理，是 metric kind 的**唯一编辑入口**（源系统页面）。Catalog 通过同步机制从本页面拉取指标定义，注册为引用。

### 3.2 页面结构

列表页 + 新建/编辑弹窗。

```
┌─────────────────────────────────────────────────────────────┐
│ 页面标题：指标管理                                             │
│ 副标题：指标语义定义 · 单位/聚合/时间窗口绑定                   │
│                                          [+ 新建指标]         │
├─────────────────────────────────────────────────────────────┤
│ 筛选：数据域下拉 / 状态下拉 / 搜索框                            │
├─────────────────────────────────────────────────────────────┤
│ 列表：metric_id | 名称 | 数据域 | 单位 | 聚合 | 时间窗口 | 状态 │
│       | 版本 | 操作（编辑/停用/版本历史）                       │
└─────────────────────────────────────────────────────────────┘
```

### 3.3 列表页

**筛选栏**：

| 筛选项 | 控件 |
|---|---|
| 数据域 | 下拉（生产域/安全域/设备域） |
| 状态 | 下拉（active / deprecated / 全部） |
| 搜索 | 文本框（按 metric_id / 名称模糊搜索） |

**列表字段**：

| 列 | 说明 |
|---|---|
| metric_id | 稳定标识（如 `coal.raw_coal_output`） |
| 名称 | 显示名称（如"原煤产量"） |
| 数据域 | — |
| 单位 | 关联的 unit（如"吨"） |
| 聚合方式 | 关联的 aggregation（如"日累计"） |
| 时间窗口 | 关联的 time_window（如"班次"） |
| 状态 | active（绿）/ deprecated（黄） |
| 版本 | 当前版本号 |
| 操作 | 编辑 / 停用 / 版本历史 |

### 3.4 新建/编辑表单

| 字段 | 控件 | 必填 | 说明 |
|---|---|---|---|
| metric_id | 文本输入 | 是 | 小写英文/下划线/点，创建后不可改。建议命名空间：`{行业}.{指标名}`，如 `coal.raw_coal_output` |
| 名称 | 文本输入 | 是 | 显示名称 |
| 描述 | 文本域 | 否 | 业务语义说明 |
| data_domain_id | 下拉选择 | 是 | 从数据域列表选择 |
| unit_ref | 下拉选择 | 是 | 从基础配置的 unit 中选择（如"吨""小时""百分比"） |
| aggregation_ref | 下拉选择 | 是 | 从基础配置的 aggregation 中选择（如"日累计""日均""班均"） |
| time_window_ref | 下拉选择 | 是 | 从基础配置的 time_window 中选择（如"班次""自然日"） |
| owner | 人员选择器 | 是 | 默认数据域负责人，可修改 |
| 计算公式 | 文本域 | 否 | 若指标为派生指标，填写计算公式说明（非执行逻辑，仅文档） |

**系统自动管理**：
- `version`：新建为 `1.0.0`；编辑语义字段（名称/描述/单位/聚合/时间窗口）产生新版本（MAJOR 或 MINOR）；仅元数据修改为 PATCH
- `content_hash`：保存时自动计算
- `status`：新建为 active；可手动停用

### 3.5 操作流

**新建**：
1. 点击"新建指标"→ 填写表单 → 提交
2. 走 CatalogChangeRequest 审批流 → 审批通过后激活
3. 激活后 Catalog 同步机制可拉取该指标，用户在 Catalog 治理中注册引用

**编辑**：
1. 点击"编辑"→ 修改字段 → 提交 → 产生新版本 → 走审批流
2. 已注册引用该指标的 pack 不受影响（仍绑定旧版本），用户可在 Catalog 中选择升级引用

**停用**：
1. 点击"停用"→ 二次确认（展示被哪些 pack/manifest 引用）→ 状态变为 deprecated
2. deprecated 的指标不再出现在新建引用的选择列表中，已注册的引用继续服务（LKG 策略）
3. 停用不可删除，保留审计记录

**版本历史**：
1. 点击"版本历史"→ 弹窗展示所有版本（version、变更时间、变更人、变更说明、content_hash）
2. 可查看任意版本的完整定义

### 3.6 权限

| 操作 | 权限 |
|---|---|
| 查看列表/详情/版本历史 | `ecmc.catalog.read`（所有认证用户） |
| 新建/编辑 | `ecmc.catalog.request`（走审批流） |
| 停用 | `ecmc.catalog.request`（走审批流） |
| 审批 | `ecmc.catalog.approve`（对应 kind owner） |

## 5. 绑定模板（binding-templates.html）

### 5.1 页面定位

绑定模板（binding_template）的语义定义管理，是 binding_template kind 的**唯一编辑入口**（源系统页面）。绑定模板定义"实体之间如何绑定""指标如何绑定到证据需求"等规则，含 params_schema（JSON Schema）。

### 5.2 页面结构

列表页 + 新建/编辑弹窗（含 params_schema 可视化编辑器）。

```
┌─────────────────────────────────────────────────────────────┐
│ 页面标题：绑定模板                                             │
│ 副标题：定义实体/指标/证据的绑定规则 · params_schema            │
│                                          [+ 新建绑定模板]      │
├─────────────────────────────────────────────────────────────┤
│ 筛选：状态下拉 / 搜索框                                        │
├─────────────────────────────────────────────────────────────┤
│ 列表：template_id | 名称 | 参数数量 | 被引用模型数 | 状态 | 版本 │
│       | 操作（编辑/停用/版本历史/查看引用）                     │
└─────────────────────────────────────────────────────────────┘
```

### 5.3 列表页

**列表字段**：

| 列 | 说明 |
|---|---|
| template_id | 稳定标识（如 `coal.equipment_binding`） |
| 名称 | 显示名称（如"设备→工作面绑定"） |
| 参数数量 | params_schema 中定义的参数个数 |
| 被引用模型数 | 使用该模板的因果模型数量（点击可查看列表） |
| 状态 | active / deprecated |
| 版本 | — |
| 操作 | 编辑 / 停用 / 版本历史 / 查看引用 |

### 5.4 新建/编辑表单

**基本信息**：

| 字段 | 控件 | 必填 | 说明 |
|---|---|---|---|
| template_id | 文本输入 | 是 | 小写英文/点/下划线，创建后不可改。建议命名空间 `{行业}.{用途}` |
| 名称 | 文本输入 | 是 | 显示名称 |
| 描述 | 文本域 | 否 | 模板用途和适用场景 |
| owner | 人员选择器 | 是 | 默认平台架构负责人 |

**params_schema 编辑器**（核心）：

提供两种编辑模式，可切换：

| 模式 | 说明 |
|---|---|
| 可视化编辑器 | 表格形式添加参数行：参数名（name）、显示标签（label）、类型（type：string/ref/number/boolean/enum）、是否必填、说明（description）。type=ref 时额外选择引用的 kind（如 entity_type/metric） |
| JSON 预览 | 实时展示生成的 JSON Schema，只读或可直接编辑（高级用户） |

**参数行字段**：

| 字段 | 控件 | 说明 |
|---|---|---|
| 参数名 | 文本输入 | 英文，如 `entity_type_ref`、`equipment_id` |
| 显示标签 | 文本输入 | 中文，如"目标实体类型"、"设备 ID" |
| 类型 | 下拉 | string / number / boolean / enum / ref（引用其他 kind） |
| 引用 kind | 下拉 | type=ref 时出现，选择 entity_type / metric / unit 等 |
| 枚举值 | 文本输入 | type=enum 时出现，逗号分隔 |
| 必填 | 复选框 | — |
| 说明 | 文本输入 | — |
| 操作 | 按钮 | 上移/下移/删除 |

**示例**（设备→工作面绑定模板）：

```json
{
  "type": "object",
  "properties": {
    "equipment_type_ref": {
      "type": "ref",
      "kind": "entity_type",
      "label": "设备类型"
    },
    "working_face_ref": {
      "type": "ref",
      "kind": "entity_type",
      "label": "工作面"
    },
    "binding_date": {
      "type": "string",
      "label": "绑定日期",
      "format": "date"
    }
  },
  "required": ["equipment_type_ref", "working_face_ref"]
}
```

### 5.5 操作流

**新建**：填写基本信息 + 编辑 params_schema → 提交审批 → 审批通过 → 激活 → Catalog 同步可拉取

**编辑**：
- 修改基本信息或 params_schema → 产生新版本 → 审批 → 激活
- params_schema 的破坏性变更（删除参数、修改类型）产生 MAJOR 版本，已使用该模板的模型需确认兼容
- 新增可选参数产生 MINOR 版本

**停用**：二次确认（展示被引用模型列表）→ deprecated → 新模型不可选用，已使用的模型继续运行（LKG）

**查看引用**：点击"被引用模型数"→ 弹窗展示使用该模板的因果模型列表（模型名、版本、状态）

### 5.6 权限

| 操作 | 权限 |
|---|---|
| 查看列表/详情/引用 | `ecmc.catalog.read`（所有认证用户） |
| 新建/编辑/停用 | `ecmc.catalog.request`（走审批流） |
| 审批 | `ecmc.catalog.approve`（平台架构负责人角色） |
