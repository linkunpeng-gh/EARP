# 后台导航改版设计（一级菜单 + 左侧抽屉）

- 日期: 2026-08-11
- 状态: 定稿（待实施，纯 earp-admin 前端重构）
- 关联: `arch/session-record.md`（RAG 收尾后优先级 P1 起）、现有 admin 13 页面、PM 导航方案评审

## 1. 背景

PM 提出后台导航改版：一级菜单在上方（现状位置），二级菜单在左侧抽屉。对 PM 方案做了 8 项逐条评审（2026-08-11 问答式讨论），本设计为定稿结论。

## 2. 导航蓝图

```
一级            左抽屉（顺序即菜单序）
────────────────────────────────────────────────
首页            快捷入口 · 知识资产看板（看板二期）
工作台          chat · workflow · Agent · Skills        ← 均"规划中"；推理留在能力中心
知识中心        数据域 · 知识库 · 分段配置 · 召回测试     ← 全部已实现
能力中心        能力注册 · 推理测试 · 连接器 · 模型配置    ← 推理=能力调试工具
应用中心        概览 · 我的应用                           ← admin=发布管理；user 端使用流程另记
插件中心        插件管理                                 ← 规划中
治理中心        Audit · Roles · Org · Tenants · Policy    ← Audit 已实现，其余规划中
运行监控        Sessions 执行 · 对话日志 · 审计          ← 已实现
```

## 3. 决策记录（8 项评审结论）

| # | 议题 | 决策 |
|---|---|---|
| 1 | 工作台层级 | **二级平铺**：chat / workflow / Agent / Skills 直接放左抽屉，砍掉"agent 管理"中间层（三级嵌套 → 二级即功能） |
| 2 | 首页 vs 运行监控 | **职责分离**：首页=业务门户（快捷入口 + 最近操作 + 知识资产看板）；运行监控=系统运维（执行流水/审计/健康）。边界原则：业务数据归业务页面，系统数据归监控 |
| 3 | 对话归属 | 对话 = **对话日志**（记录/排查/质量回看），归**运行监控**（与 sessions 执行、audit 组成观测三件套，参考 Dify Logs）。运营分析看板（对话量/满意度）二期放首页业务侧，不进监控 |
| 4 | chat vs chatflow | **chat**=简单对话（本次概念）；**chatflow**=可视化对话编排（未来立项，本次不做）。菜单用 **chat**。chat 第一期"规划中"，落地依赖 P1 问答链路（对话页 + 检索引用 + 回答生成）。推理（plan/stream）=能力调试工具，留能力中心，**不是对话** |
| 5 | connector/MCP 归属 | 连接器（MCP/REST/DB 三类）是 capability 的**执行后端**，归**能力中心**（架构一致，配置闭环）。工作台**不放 MCP**（应用通过能力间接引用连接器）。菜单名"连接器"，首期实现 MCP，REST/DB 占位 |
| 6 | 模型配置归宿 | 模型（LLM/embedding/rerank）是能力执行底座，归**能力中心**（子项"模型配置"）。密钥治理长期话题另行深化 |
| 7 | 空壳菜单 | **策略 A：一级全挂 + "规划中"标记**。未实现二级显示弱化"规划中"，点击进占位页（显示 roadmap 与关联优先级），不假装有功能。治理中心现有 5 个 disabled 统一改为"规划中"口径 |
| 8 | admin vs user 边界 | 应用中心=**admin 发布管理视图**（发布/下架/状态）；**user 端**使用流程（应用商店/我的应用）在 earp-user，本轮不动，流程记录（见 §5） |

## 4. 实施范围与分期

- **范围**：纯 **earp-admin 前端**重构。后端 API 不动（首页快捷入口用现有 API；知识资产看板二期要聚合接口再动后端）
- **第一期（本次改版）**：导航框架（一级 + 左抽屉）+ 已有页面归位（知识/能力/治理/监控点亮）+ 首页（快捷入口 + 最近操作）+ 规划中占位页 + 治理中心 disabled 统一改"规划中"
- **第二期**：P1 问答链路 → chat 落地 + 引用溯源 + 对话日志引用展示
- **第三期起**：workflow 配置 UI、连接器配置页、Agent、Skills、应用中心（随 roadmap 逐一点亮）

## 5. 应用发布流程（产品流程记录，user 端后续实现）

```
管理员（工作台）配置 chat/workflow 等能力
  → 测试（能力中心推理测试/召回测试）
  → 评审
  → 发布到应用中心（admin 视图：上架/下架/状态）
  → 普通 user（earp-user）在应用中心看到已发布应用
  → 加载到"我的应用"（user 侧）
```
