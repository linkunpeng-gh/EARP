# Chatflow 流程编排使用说明（FDE）

> 写给 FDE（业务专家）：**不用写代码**，在画布上把「智能体怎么干活」搭成一张流程图——
> 先干什么、后干什么、什么情况走哪条分支、要不要人工把关，全部拖拽、调试、发布。
>
> 技术细节（节点数据形状、权限审计边界、实现原理）见 `earp-fde-user-guide.md` §15。

---

## 0. 30 秒看懂 Chatflow

Chatflow 是**独立于 Chat 的一种应用**（工作台抽屉里两个并列标签）：

| | Chat 聊天助手 | **Chatflow 流程编排（本文主角）** |
|---|---|---|
| 怎么干活 | 机器全自动（理解→检索→回答） | 你在**画布**上拖一张图规定步骤 |
| 入口 | 工作台 → **chat** | 工作台 → **chatflow**（独立标签） |
| 适合 | 通用知识问答 | **流程固定的场景**（如"先查设备状态→坏了就建工单→人工确认"） |

一张流程图画布长这样：

```
[开始] → [QU 理解] → [能力调用:查状态] → [工具:取中台数]
     → [条件: 状态==故障?]
          ├─ ✓是 → [人工确认] → [LLM 生成工单] → [结束]
          └─ ✗否 → [LLM 生成"正常"答复] → [结束]
```

**骨架（先干什么后干什么）是你拖的；节点内部怎么理解、怎么查，是机器自动的。**

---

## 1. 从哪进去

**工作台 → 抽屉里点「chatflow」**（与 chat 并列的独立标签）→ Chatflow 应用列表页：

- 点「**＋ 新建流程**」→ 填名称 → 进画布编辑页
- 或点已有流程（卡片带 ⛓Chatflow 徽标）进入编辑

> chat 应用的列表**只显示聊天助手**；flow 应用全在 chatflow 页——两者互不混杂。

---

## 2. 画布编排页长什么样（Dify 式三栏）

```
┌─────────┬──────────────────────────┬───────────────┐
│ 节点面板  │         画布             │  属性面板       │
│ ▸ 开始   │  [开始] → [LLM]          │  选中节点配置   │
│ ▸ LLM   │     ↓                    │  提示词: …     │
│ ▸ 知识检索│  [条件] → [人工确认]      │  (字段随节点变)  │
│ ▸ QU    │   (拖节点+连线+平移+缩放)  │               │
│ ▸ 能力…  └──────────────────────────┴───────────────┘
└─────────  顶部栏：流程名 + ▶运行 + 保存 + 发布
```

- **左·节点面板**：10 种积木，**拖到画布**（或双击快速添加）
- **中·画布**：拖节点、连线（右圆点 → 左圆点）、平移（拖空白）、缩放
- **右·属性面板**：点选中节点，编辑它的参数（字段随节点类型变化）
- **顶部**：▶ 运行（测试）、保存、发布

---

## 3. 节点字典（这 10 种"积木"）

| 节点 | 干什么 | 属性面板里配（必填） |
|:---|:---|:---|
| **开始 / 结束** | 流程起点 / 终点 | 无（一张图各一个） |
| **LLM** | 生成文字/回答 | 提示词 `prompt` |
| **知识检索** | 知识库检索 | 检索词、TopK |
| **QU 理解** | **自动理解问题**再查 | 理解问题（默认用用户问题） |
| **能力调用** | 调系统能力（带权限+审计） | 能力 ID（来自能力中心） |
| **工具取数** | 经中台连接取数 | 连接 ID（来自中台对接） |
| **对话历史** | 取最近对话 | 轮数 |
| **条件分支** | 条件分流（俩出路） | 左值(前节点输出)、操作符、右值 |
| **人工确认** | **停下来等人工** | 确认问题 |

> **条件节点**有 2 个输出口：第 1 个输出 = ✓是，第 2 个输出 = ✗否（连线时注意）。
> **mcp 节点暂未支持**——别放。

---

## 4. 变量引用（让节点之间传值）

在属性面板的文本框中可直接写：

| 写法 | 含义 |
|:---|:---|
| `{{query}}` | 用户这次的问题 |
| `{{#节点id.output.字段#}}` | 某个前序节点的输出（如 `{{#q1.output.citations#}}` 取 QU 的引文） |
| `{{#节点id.output.reply#}}` | 人工确认节点的答复 |

例：LLM 节点提示词 `用户答复：{{#h1.output.reply#}}。请生成工单摘要。`
→ 运行时自动替换成"用户答复：同意派单。请生成工单摘要。"

## 5. 三步搭好一个流程

1. **点「示例」**按钮载入模板打底（全节点示例），删掉/改不需要的
2. **从左边拖节点、连边**，点节点在右边配参数（capability_id / connector_id / 提示词…）
3. **点「保存」**——图不合法会提示（缺开始/结束、有环、条件分支只连一条…）→ 修正再存

> 保存后点「▶ 运行」就能测（见 §6）；已发布应用改完**回到草稿**，需重新发布。

---

## 6. 调试（跑你的流程）

1. 点「**▶ 运行**」→ 输入一句测试问题 → 弹出**运行结果**：答案 + 每个节点输出
2. **遇条件分支** → 按命中分支走，另一支不执行
3. **遇人工确认** → 弹出「⏸ 等待确认」→ 在输入框**输答复** → 点提交 → 流程继续跑完
4. **出错** → 红色提示（权限 403 / 图画错 / 执行失败），按提示改

> 同一会话可多个人工确认点，逐个等待、逐个答复。

## 7. 三个常用场景示例

### 场景 A：知识问答（最简单）
```
开始 → 知识检索 → LLM 生成回答 → 结束
```

### 场景 B：设备维修单（确定性流程 + 人工把关）
```
开始 → QU 理解（"CNC-01 温度异常"）→ 能力调用:查状态
     → 条件: 状态==故障?
          ├─ ✓是 → 能力:建工单 → 人工确认（确认派单）
          │       → 能力:通知负责人 → 结束
          └─ ✗否 → LLM 生成"设备正常"答复 → 结束
```

### 场景 C：客户投诉分流（规则分支）
```
开始 → 知识检索:查历史投诉 → 条件: 是否 VIP?
      ├─ ✓是 → 专人话术 → 结束
      └─ ✗否 → 标准话术 → 结束
```

## 8. 常见问题（FAQ）

| 现象 | 可能原因 / 处理 |
|:---|:---|
| 保存提示"图不合法" | 缺开始/结束、有环、条件分支只连一条边——看提示逐个改 |
| 能力节点 403 | 你的角色没该能力权限（找管理员授权） |
| 工具节点报"连接不存在" | connector_id 填错或连接已删/停用（找管理员） |
| 运行到一半不动 | 遇到人工确认在等人——在弹窗输答复提交即可 |
| 等人太久没答复 | 默认 1 小时后自动判"超时终止" |
| 找不到 Chatflow 入口 | 工作台（一级菜单）→ 左抽屉点 **chatflow**（不是 chat） |
| 画布看不到节点 | 滚轮缩放 / 拖空白平移；卡住就点「清空」再载入「示例」 |

---

## 9. 权限与安全速记

- **能力节点**：每次调用走权限门禁 + 审计（`earp.capability.call.*` 落日志）
- **工具取数**：数据在外部系统，**不自动按角色过滤**（标注 `domain_filtered: false`）——敏感数据请确认归属
- **人工确认**：等待超时自动终止，不留僵尸流程
